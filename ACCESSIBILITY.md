# Accessibility

Quirk Systems wants people to be able to discover, use, and contribute to its
work with different devices, input methods, and assistive technologies. This
page is a starting point for reporting barriers and improving experiences
across the organization.

## Current status

Accessibility varies by repository and experience. We have not established a
single list of supported devices or assistive technologies, or an
organization-wide WCAG conformance result. A repository may describe its own
tested environments and known barriers. An unlisted environment should be
treated as unverified, not as unsupported or supported.

## Report a barrier

Open an issue in the repository where you encountered the barrier, if its
issues are available. Choose its bug-report form when present. If you cannot
identify the repository, use the
[organization bug report](https://github.com/Quirk-Systems/.github/issues/new?template=bug_report.yml).

If you can, tell us:

- What you were trying to do and what happened.
- The page or experience, and the build or version if visible.
- Your browser, operating system, device, and assistive technology versions,
  if they are relevant and you are comfortable sharing them.
- The steps to reproduce the barrier and what would have helped.

Share only what you are comfortable making visible in a GitHub issue. Do not
post passwords, private account information, or other sensitive material.
For a security vulnerability, use the private route in
[SECURITY.md](SECURITY.md), not a public issue. See [SUPPORT.md](SUPPORT.md)
for other support routes. A report does not need to include a diagnosis.

## Contribute an improvement

Start with the affected repository's contribution guidance and
[CONTRIBUTING.md](CONTRIBUTING.md). Consider keyboard operation, visible focus,
text alternatives, understandable instructions and errors, small screens,
zoom, and reduced motion where relevant. Describe what you tested, the exact
build and environment, what happened, and what remains untested. Involve
people who use the relevant access methods when possible.

The [W3C WCAG 2.2 quick reference](https://www.w3.org/WAI/WCAG22/quickref/)
and [W3C mobile accessibility guidance](https://www.w3.org/WAI/standards-guidelines/mobile/)
can help select appropriate checks. A short checklist or a passing automated
test alone does not establish conformance.

This organization-level page is a default where a repository does not provide
its own accessibility page. Repository maintainers should document
experience-specific environments, barriers, and reporting paths when they
have verified them.
