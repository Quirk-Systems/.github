# Quirk Systems

**A stateful human–agent operating system for turning evolving intent into
governed action, durable knowledge, and an inspectable shared world.**

Quirk connects humans, agents, repositories, tools, evidence, and decisions
through one persistent operating loop:

```text
async preparation → real-time session → async execution → real-time review → persistent world update
```

The governed, versioned state connecting those participants is the system.

## Public ecosystem

- [`project-scaffold`](https://github.com/Quirk-Systems/project-scaffold) —
  public runnable reference scaffold; it is not the kernel.
- [`quirk-os`](https://github.com/Quirk-Systems/quirk-os) — public candidate
  kernel boundary, pending human admission and corrected evidence.
- [`quirk-core`](https://github.com/Quirk-Systems/quirk-core) — candidate
  Preference Graph language and storage doctrine; no admitted runtime or
  declared consumer.
- [`quirk-feed`](https://github.com/Quirk-Systems/quirk-feed) — discovery
  interface with its own application boundary.
- [`quirk-generator`](https://github.com/Quirk-Systems/quirk-generator) —
  bounded multi-model visual-generation instrument.
- [`.github`](https://github.com/Quirk-Systems/.github) — public organization
  governance, topology facts, and reusable workflows.

## Operating principles

- **Git-canonical, runtime-projected.** Canonical definitions are versioned and
  reviewed; databases and interfaces are projections.
- **Human authority over consequential change.** Agents prepare, propose,
  execute bounded work, and return evidence.
- **Containment before capability.** Every agent and automation receives
  explicit objectives, permissions, limits, and shutdown authority.
- **Second consumer before extraction.** Shared modules become packages or
  repositories only when a real reuse, security, scaling, or release boundary
  justifies the split.
- **Every decision updates the world.** Accepted work changes canonical state,
  not merely a conversation or task status.

The complete topology, adjacent commerce boundary, and open manual PR
dispositions are validated in
[`.quirk/repositories.json`](../.quirk/repositories.json) and
